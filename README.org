#+TITLE: lark-org.el — Org chat UI for Lark Messenger

Render Lark Messenger chats as Org buffers, per ORG-CHAT-STANDARD
v1.1 (sections 1-8):

- =*Lark Org*= — the chat list (section 3 grammar)
- =*Lark Org: <chat>*= — one conversation (section 4 grammar)

Backend: Lark Open Platform REST.  Lark international defaults to
=https://open.larksuite.com=; set =lark-org-api-base= to
=https://open.feishu.cn= for Feishu.  Built-in libraries only — no
backend package dependency (url.el transport behind
=lark-org-http-function=, plus json, org, auth-source, cl-lib).

* Setup

1. Create a Lark app (open.larksuite.com, or open.feishu.cn for
   Feishu) with =im:message= scopes.
2. =(setq lark-org-app-id "cli_xxx")=.
3. Store the app secret in auth-source:

#+begin_example
machine lark-org login app-secret password <secret>
#+end_example

   (=lark-org-secret-auth-source= selects the host/user pair.)
4. =M-x lark-org=.

The secret and the cached tenant_access_token live in memory only;
neither ever enters a buffer, message, or log.

* Install / test

#+begin_example
make compile   # byte-compile with warnings as errors
make test      # ERT suite, transport stubbed, no network
#+end_example

Requires Emacs 28.1+.  Conforms to ORG-CHAT-STANDARD v1.1
(https://github.com/khaalidrafi/telega-org, file
ORG-CHAT-STANDARD.org).

* Android / touch

The package is Android-compatible by law (Owner 2026-11-06 #hq:
"Comms pkgs must be Android-compatible"): it is pure elisp over
url.el — no subprocess, no graphic-only API, nothing desktop
assumed — and it runs on the official Emacs Android app
(org.gnu.emacs), Termux Emacs, and touch tablets.  On a detected
touch device (=lark-org--touch-device-p=: =system-type= = 'android,
the =TERMUX_VERSION= variable, or a =touch-screen= terminal
parameter) =lark-org-touch-mode= binds a single tap to open, taps
fold headings, lines cut at the window edge and scrolling follows
the finger (=scroll-conservatively= 101, =truncate-lines= t).  No
feature depends on hover.  url.el on Android uses the same TLS
stack as elsewhere; the app secret stays in auth-source, in
memory only.

* Disclosed limits (v0.1 -> v0.2)

- The chats endpoint carries no unread/mention model and no last
  message preview.  Since v0.2 the read-marker unit closes the gap:
  a local marker (stamped when a chat view renders, persisted in
  =lark-org-read-state-file=) counts unread messages, and the real
  preview renders from bounded history, at the cost of one bounded
  history read per chat per refresh.  =lark-org-markers= nil (or a
  failed read) restores the v0.1 placeholders: tags 0, "...".
  Mentions stay 0 — the endpoint exposes no mention model.
- History authors are sender ids (the endpoint exposes no member
  names); history is bounded to =lark-org-max-pages= pages.
