#+TITLE: lark-org.el — Org chat UI for Lark Messenger

Render Lark Messenger chats as Org buffers, per ORG-CHAT-STANDARD
v1.1 (sections 1-8):

- =*Lark Org*= — the chat list (section 3 grammar)
- =*Lark Org: <chat>*= — one conversation (section 4 grammar)

Backend: Lark Open Platform REST (default route ='api=) or the
official Lark CLI (route ='cli=, v0.3 — user identity, no app
credentials).  Lark international defaults to
=https://open.larksuite.com=; set =lark-org-api-base= to
=https://open.feishu.cn= for Feishu.  Built-in libraries only — no
backend package dependency (url.el transport behind
=lark-org-http-function=, plus json, org, auth-source, cl-lib).

* Setup

1. Create a Lark app (open.larksuite.com, or open.feishu.cn for
   Feishu) with =im:message= scopes.
2. =(setq lark-org-app-id "cli_xxx")=.
3. Store the app secret in auth-source:

#+begin_example
machine lark-org login app-secret password <secret>
#+end_example

   (=lark-org-secret-auth-source= selects the host/user pair.)
4. =M-x lark-org=.

The secret and the cached tenant_access_token live in memory only;
neither ever enters a buffer, message, or log.

* CLI route (v0.3) — no app, no app-quota billing

The Open Platform REST route above needs a Lark app (id + secret)
and spends app quota — "API has costs" (Owner, 2026-11-23).  The
official Lark CLI (https://github.com/larksuite/cli) runs the same
/open-apis endpoints under YOUR USER identity, so lark-org can ride
it with no app credentials at all:

1. Install once — either way:
   - =M-x lark-org-cli-install= (v0.4): pure Elisp — resolves the
     newest release, downloads the tarball for this machine,
     verifies the sha256 against the release =checksums.txt=, and
     untars the single static binary (built-ins only: url.el,
     zlib, an in-Elisp tar scanner; no npm).  Termux's =$PREFIX/bin=
     by default, =~/.local/bin= elsewhere; =C-u= prefix pins a
     version and skips the GitHub API call.
   - =sh termux/install.sh= from this repo (Termux, no Emacs), or
     =npx @larksuite/cli@latest install= on a Node machine.
     The =termux/lark-cli/= directory carries the same repack as a
     proper Termux package (=build.sh=, termux-packages format).
2. Log in once: =M-x lark-org-cli-login= (runs =lark-cli auth
   login --recommend=; copy the printed URL into a browser when
   none opens).
3. =(setq lark-org-route 'cli')=, then =M-x lark-org=

=lark-org-cli-program= names the binary (default =lark-cli=).
lark-org only builds the argument vector and parses the JSON
answer; the CLI keeps its own credentials in the OS keychain and
they never reach Emacs.  A missing or failing CLI signals its
reason (the demo fixtures only under =lark-org-demo=, below); the
send path signals instead of faking.  The CLI route shells out with
=call-process= — a desktop and Termux route; the default stays
='api= so the Android-compat law below keeps holding.

* No fake data (v0.3 law)

v0.2 silently degraded every failed read to built-in demo chats
("Alice", "hq"), so a broken credential or a missing scope looked
like messages you do not have (Owner, 2026-11-23: "It shows Alice
and hq messages I don't even have").  v0.3 ends that:

- A failed read signals the backend's own reason with the route
  context (route, base URL or CLI program, and the way out); the
  chat list renders only what the backend really answered — zero
  chats is an empty list.
- Route ='api= is a tenant/app identity: it lists the chats the
  APP was added to, not your whole account.  For your own
  messages use the CLI route above.
- =(setq lark-org-demo t)= opts back into the demo fixtures for
  reads — trying the UI without an account.  Sends still signal.

* Install / test

#+begin_example
make compile   # byte-compile with warnings as errors
make test      # ERT suite, transport stubbed, no network
#+end_example

Requires Emacs 28.1+.  Conforms to ORG-CHAT-STANDARD v1.1
(https://github.com/khaalidrafi/telega-org, file
ORG-CHAT-STANDARD.org).

* Android / touch

The package is Android-compatible by law (Owner order 2026-11-06:
comms packages must be Android-compatible): it is pure elisp over
url.el — no subprocess, no graphic-only API, nothing desktop
assumed — and it runs on the official Emacs Android app
(org.gnu.emacs), Termux Emacs, and touch tablets.  The CLI route is
opt-in and works on Termux Emacs after =M-x lark-org-cli-install=
(the static binary lands in =$PREFIX/bin= — see =termux/README.org=);
the org.gnu.emacs app stays on ='api= (Android 10+ forbids executing
files from app-home directories, so no subprocess route exists
there).  The package never requires the CLI, and the default ='api=
route stays pure elisp.  On a detected
touch device (=lark-org--touch-device-p=: =system-type= = 'android,
the =TERMUX_VERSION= variable, or a =touch-screen= terminal
parameter) =lark-org-touch-mode= binds a single tap to open, taps
fold headings, lines cut at the window edge and scrolling follows
the finger (=scroll-conservatively= 101, =truncate-lines= t).  No
feature depends on hover.  url.el on Android uses the same TLS
stack as elsewhere; the app secret stays in auth-source, in
memory only.

* Disclosed limits (v0.1 -> v0.2)

- The chats endpoint carries no unread/mention model and no last
  message preview.  Since v0.2 the read-marker unit closes the gap:
  a local marker (stamped when a chat view renders, persisted in
  =lark-org-read-state-file=) counts unread messages, and the real
  preview renders from bounded history, at the cost of one bounded
  history read per chat per refresh.  =lark-org-markers= nil (or a
  failed read) restores the v0.1 placeholders: tags 0, "...".
  Mentions stay 0 — the endpoint exposes no mention model.
- History authors are sender ids (the endpoint exposes no member
  names); history is bounded to =lark-org-max-pages= pages.
